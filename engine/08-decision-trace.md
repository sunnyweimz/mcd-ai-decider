# 08 · 决策链路快照与透明化（Decision Trace）

> 推荐系统最被诟病的是"黑盒"。本模块让「决策官」的每一次推荐都**可追溯、可审计、可解释到过程**。
> 这不仅是技术透明度，也是比赛里体现"推荐决策透明化"专业度的亮点。

## 一、决策快照是什么

每次完整推荐，旁路产出一份 **Decision Trace**：记录这次推荐"候选从哪来、被谁淘汰、怎么排的、为什么最终是它"。
它默认在后台生成；当用户问「你是怎么给我推的 / 为什么是它 / 展开说说」时，决策官可把它翻译成人话展示。

## 三、给用户看的"轻量版"透明化

用户通常不想看 JSON。当被问"怎么推的"，用这种人话层级展示：

```
🔍 这次我是这么帮你决定的：
  1) 从徐庄店当前在售里，捞了 11 个候选（你常点的 + 符合口味的 + 能用券的 + 1个新品）
  2) 排除了「整套四件套」——你说不太饿，整套吃不完
  3) 因为你有 2 张券今晚到期，我把能用券的方案提了权重
  4) 最后按「轻食 + 省钱」给你排了序，主推用掉到期券的那套
如需更细的打分明细，我也能展开给你看。
```

## 四、透明化的三个层级（按需展开）

| 层级 | 展示内容 | 触发 |
|---|---|---|
| L0 结论 | 只给 Top3 + 简要理由 | 默认 |
| L1 过程 | 召回数量/排除项/兜底逻辑（上面的人话版） | 用户问"怎么推的" |
| L2 明细 | 六维打分、权重向量、MMR、EE 状态 | 用户问"展开打分/为什么分这么算" |

## 五、价值

- **信任**：用户看得见过程，才敢把"决定吃什么"交给它。
- **可审计**：每次推荐可复盘，便于迭代与纠错（也便于比赛评委核验真实性）。
- **可解释闭环**：Trace + 反事实解释（04）+ 反馈学习（06）共同构成"透明的个性化推荐决策"，这是本作品的核心差异化。
