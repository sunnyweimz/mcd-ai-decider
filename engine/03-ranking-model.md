# 03 · 多目标精排模型（Ranking Model）

> 精排层的任务：对召回来的每个候选，算出一个**可复现、可解释**的综合得分 `score ∈ [0,1]`，用于排序。
> 核心是：6 个归一化子分 + 场景化权重向量 + 硬约束过滤。所有计算都基于麦当劳 MCP 的真实数据。

## 一、评分函数

对候选 `c`，综合得分为各维度加权和：

```
score(c) = Σ_i  w_i · f_i(c)          其中 Σ_i w_i = 1,  f_i(c) ∈ [0,1]
```

- `f_i(c)`：第 i 个维度的子分，已归一化到 [0,1]，越大越好。
- `w_i`：该维度在当前场景下的权重（见"场景权重矩阵"）。
- 结果 `score(c) ∈ [0,1]`，便于跨场景比较与解释。

## 二、六个子分维度（Feature Scores）

| 符号 | 维度 | 含义 | 计算思路（基于真实数据） |
|---|---|---|---|
| `f_taste` | 口味匹配 | 与画像口味向量/本轮口味的契合度 | 候选 tags 与 UserProfile 口味向量余弦相似 + 命中显式口味加分；命中忌口直接判 0（并进硬过滤） |
| `f_value` | 性价比 | 单位价格的满足感 + 优惠力度 | 基于 `calculate-price` 的 `discount/originalPrice` 与"份量/价格"比；命中券/套餐优惠显著加分 |
| `f_health` | 健康契合 | 对热量/营养目标的满足度 | 用 `list-nutrition-foods` 汇总候选总 kcal/蛋白；控热量场景越低越好，扛饿场景高蛋白越好 |
| `f_benefit` | 权益契合 | 能否用上券 / 消耗将过期积分 | 命中 `query-store-coupons` 可用券 +；可消耗 `query-my-account` 将过期积分 ++ |
| `f_novelty` | 新鲜度 | 适度避开吃腻、鼓励没吃过 | 近 N 单出现越多则越低（抗腻）；探索项(R4)给新鲜度高分 |
| `f_scene` | 场景适配 | 与就餐场景的匹配 | 赶时间偏简单单品、多人偏分享餐、外送偏耐放、不太饿偏小份 |

### 归一化约定
- 价格、热量这类"绝对值"维度，用场景内的 min-max 归一化（在候选集内相对比较）。
- 相似度类（口味）本身即 [0,1]。
- 任一维度缺数据时，取中性值 0.5，并在决策快照里标注"该维度数据缺失"。

## 三、场景权重矩阵（Scene Weight Matrix）

不同场景下，六维权重不同。下表为默认权重（行和为 1，可按强度微调）：

| 场景 | f_taste | f_value | f_health | f_benefit | f_novelty | f_scene |
|---|---|---|---|---|---|---|
| **默认/没说** | 0.30 | 0.25 | 0.10 | 0.15 | 0.10 | 0.10 |
| **省钱优先** | 0.15 | 0.35 | 0.05 | 0.30 | 0.05 | 0.10 |
| **减脂/控热量** | 0.20 | 0.10 | 0.45 | 0.10 | 0.05 | 0.10 |
| **扛饿/能量** | 0.25 | 0.20 | 0.25（高蛋白向） | 0.10 | 0.05 | 0.15 |
| **犒劳自己** | 0.40 | 0.10 | 0.05 | 0.10 | 0.25 | 0.10 |
| **赶时间** | 0.25 | 0.20 | 0.05 | 0.15 | 0.05 | 0.30 |
| **多人聚餐** | 0.25 | 0.25 | 0.05 | 0.15 | 0.05 | 0.25 |
| **探索/来点新的** | 0.25 | 0.15 | 0.05 | 0.10 | 0.35 | 0.10 |

> 场景识别：从对话关键词 + UserProfile 推断。多个场景叠加时（如"减脂又想省"），对相关行做加权平均再归一化。
> 权重可被"今日到期券/将过期积分"等强信号临时抬升 `f_benefit`（见 04 兜底规则）。

## 四、硬约束过滤（在打分前执行，一票否决）

以下任一不满足，候选直接出局（score 不参与排序），并在决策快照记录淘汰原因：

- **忌口冲突**：命中 UserProfile.dislikes 或本轮忌口（如"不吃牛""过敏"）。
- **预算硬上限**：候选真实到手价 > 用户预算上限 ×（1+容忍系数，默认 0）。
- **热量红线**：减脂场景下候选总 kcal > 用户设定红线。
- **场景不可售**：如外送场景下该项不支持配送。

## 五、一个可复现的计算示例（真实数据）

场景：减脂，热量红线 700kcal。候选两项（均来自真实菜单 + 真实核价 + 真实营养库）：

| 候选 | 总kcal | 到手价 | f_taste | f_value | f_health | f_benefit | f_novelty | f_scene |
|---|---|---|---|---|---|---|---|---|
| 麦香鱼+苹果片 | 357 | ¥22.13 | 0.6 | 0.7 | 0.95 | 0.3 | 0.5 | 0.8 |
| 板烧鸡腿堡+小鲜萃 | 404 | ¥28 | 0.9 | 0.6 | 0.80 | 0.4 | 0.3 | 0.7 |

用"减脂"权重 (0.20,0.10,0.45,0.10,0.05,0.10)：

```
score(麦香鱼套) = .20·.6 + .10·.7 + .45·.95 + .10·.3 + .05·.5 + .10·.8
               = .12 + .07 + .4275 + .03 + .025 + .08 = 0.7525
score(板烧套)   = .20·.9 + .10·.6 + .45·.80 + .10·.4 + .05·.3 + .10·.7
               = .18 + .06 + .36 + .04 + .015 + .07 = 0.725
```

→ 精排 Top1 = 麦香鱼套（0.7525），板烧套次之（0.725）。两者接近，重排层会据多样性/口味把板烧作为"解馋版"备选保留（见 04）。

> 分数仅用于内部排序与生成解释，**不要把公式和数值直接倒给用户**，要翻译成人话理由。
