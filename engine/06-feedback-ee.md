# 06 · 反馈闭环与探索利用（Feedback Loop & Explore-Exploit）

> 推荐系统值钱的地方不在"推一次"，而在"推错了会学、推对了会强化"。
> 本文件定义：如何把用户的自然语言反馈转成信号驱动下一轮，以及如何用探索与利用（EE）在"稳妥"和"惊喜"之间取得平衡。

## 一、反馈信号体系（Feedback Signals）

把用户的口语反馈映射为结构化信号，回写画像（05）并影响下一轮召回/精排：

| 用户说法（示例） | 信号 | 处理动作 |
|---|---|---|
| "就它了 / 下单吧" | `accept` | 该项 taste 维度 +；frequent_items 计数 +；强化偏好 |
| "换一个 / 还有吗" | `reject_soft` | 当前 Top 降权，拉入召回里的次优 + 提高多样性 λ |
| "太贵了 / 便宜点" | `too_expensive` | price_anchor 下调；下一轮 f_value/f_benefit 权重↑ |
| "吃腻了 / 老是这个" | `bored` | 对该项施加 novelty 惩罚；提高 R4 探索召回占比 |
| "想吃点新鲜的" | `want_novel` | 切 Explore 模式；ε 调大 |
| "要辣的 / 不要牛肉" | `constraint` | 写入显式约束/忌口；重算召回 |
| "清淡点 / 控制热量" | `health` | 设 health_goal；切减脂权重 |

> 反馈是**即时生效**的：用户一句"太贵了"，下一轮推荐的价格带应肉眼可见地下移，并在理由里体现"听你的，这次帮你压了价"。这种"听得懂人话、马上改"的体感是核心亮点。

## 二、探索与利用（Explore-Exploit, EE）

### 为什么需要 EE
- 纯利用（只推高频/高分）→ 用户陷入信息茧房，永远吃那几样，久了腻。
- 纯探索（总推新的）→ 不稳、踩雷率高。
- EE 的意义：**大部分时候给稳妥的（利用），小概率给一个精心挑的新品（探索）**，兼顾满意度与新鲜发现。

### ε-贪心策略（ε-greedy）
- 以概率 `1−ε` 走利用：Top3 全部来自高分候选。
- 以概率 `ε` 走探索：把 Top3 的某一个位子（通常是 🥉）替换为 R4 新品探索召回的项。
- `ε` 动态调整：
  - 默认 ε = 0.2。
  - 用户多次 `bored` → ε ↑（最高 ~0.5），系统更敢给新东西。
  - 用户偏保守/明确"老样子" → ε ↓（最低 0）。
  - 用户 `want_novel` → 本轮临时 ε = 1（Explore 模式）。

### 探索项的约束
- 探索 ≠ 乱推：探索项必须与 `taste_vector` 有一定相似度（"你没吃过但大概率会喜欢"），且在预算/忌口硬约束内。
- 探索项必须**显式标注**（🧪 探索一下），并说明推荐依据，用户才会信任探索而非觉得被塞广告。
- 探索结果回写：用户接受 → 该新品进入偏好；拒绝 → 降低同类探索概率。

## 三、一次反馈闭环的完整例子

```
轮1：推 板烧四件套 ¥35（利用，命中复购）
用户："太贵了"                → 信号 too_expensive
      · price_anchor 37→28
      · 下一轮 f_value↑ f_benefit↑
轮2：推 板烧单品+今日到期薯券 ¥24 / 人气随心配 ¥14.9（更省）
      并解释"听你的，这次帮你把价压到 ¥15 档，还用掉今晚到期的券"
用户："老是鸡腿堡，腻了"       → 信号 bored
      · 板烧 novelty 惩罚；ε 0.2→0.35
轮3：Top3 中 🥉 换成 🧪 龙焰鸡腿堡(新品，口味相近) 作为探索项
用户："这个看着不错，就它"     → 信号 accept
      · 龙焰进入偏好；探索成功，tried_new 追加
```

→ 系统在三轮内完成"降价 + 换新口味 + 命中"，这就是会学习的推荐系统，而非静态问答。

## 四、与其它模块的接口

- 反馈信号回写 → UserProfile（05）。
- ε 与新鲜度 → 影响召回 R4 占比（02）与精排 f_novelty（03）。
- 每轮反馈处理记入决策快照（08），形成可追溯的学习轨迹。
