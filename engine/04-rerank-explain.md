# 04 · 重排与可解释归因（Rerank & Explainability）

> 精排给出的是"按分数排好的列表"，但直接取 Top3 往往会出现三个几乎一样的鸡腿堡套餐。
> 重排层负责把结果变成"用户真正受用的 Top3"：有区分度、有兜底、能讲清楚为什么。
> 这是推荐系统里"业务 sense"和"可解释性"落地的地方。

## 一、重排目标

从精排 Ranked List 产出最终 **Top3（含 1 个明确主推 🥇）**，满足：
1. **多样性**：三个方案覆盖不同偏好（稳妥 / 解馋 / 极致省 或 稳妥 / 惊喜 / 轻量）。
2. **兜底正确**：该用的券、该消耗的积分不能漏。
3. **可解释**：每项有 Reason，主推有反事实解释。

## 二、重排规则（按优先级执行）

### 规则 1 · 优惠/过期资产兜底置顶
- 若存在**今日到期券**或**本月将过期积分**，且有候选能用上 → 该候选 `f_benefit` 临时 +Δ，优先进入 Top3，并在理由里强调"再不用就浪费了"。
- 这是从真实用户痛点出发的业务重排，不是单纯按分数。

### 规则 2 · 多样性去同质（MMR 思想）
- 采用最大边际相关（MMR）思路挑选：
  `MMR = argmax [ λ·score(c) − (1−λ)·max_sim(c, 已选集) ]`
- `sim` 用候选的"主食类目 + 价格带 + 口味标签"相似度。λ 默认 0.7（偏相关，但强制拉开差异）。
- 效果：Top3 不会是三个板烧套餐，而是"鸡/鱼/牛"或"套餐/轻食/甜点"错开。

### 规则 3 · 角色分配（给三个位子贴标签）
按场景给 Top3 分配人设，让用户一眼看懂定位：
- 🥇 **主推**：综合分最高、最稳的那个。
- 🥈 **第二位**：与主推形成对照（省钱场景→更省的；减脂→解馋的；探索→新品）。
- 🥉 **第三位**：极端选项（极致省 / 极致轻 / 惊喜探索）。

### 规则 4 · 同分裁决
score 接近（差 < 0.03）时，依次比较：能用券 > 能消耗将过期积分 > 更贴口味画像 > 更新鲜。

## 三、可解释归因（Explainability）

每个方案都要能回答两个问题，这是"决策官"区别于"推荐列表"的灵魂。

### A. 正向理由 Reason Code（为什么推它）
用结构化模板生成人话，覆盖命中的关键维度，最多讲 2–3 条，别堆砌：

| 归因类型 | 触发条件 | 话术模板（示例） |
|---|---|---|
| 复购 | 命中 R1 高频 | "你最近 N 单点过 M 次，闭眼入不踩雷" |
| 口味 | f_taste 高 | "正好是你爱的{口味标签}" |
| 省钱 | 命中券/高 f_value | "命中你手里的『{券名}』，到手只要 ¥{价}" |
| 防浪费 | 今日到期券/将过期积分 | "这张券今晚到期，用掉等于白捡" |
| 健康 | 满足热量目标 | "全餐约 {kcal} kcal，在你 {红线} 红线内" |
| 探索 | 命中 R4 | "🧪 探索一下：你没点过，但按你的口味大概率会喜欢" |

### B. 反事实解释 Counterfactual（为什么没推 X）
这是加分项，专门解释"你平时最爱的/你以为会推的那个，为什么这次没推"：

- 触发：当用户高频项或显式期待项**未进 Top3**时，主动给一句反事实。
- 模板：
  - "没给你推{高频项 X}，是因为今天你说要{约束}，它{超了 kcal / 超预算 ¥N / 和忌口冲突}。想吃的话我也能帮你下，就是会{破戒/超预算}。"
- 价值：让用户感到系统"懂取舍、讲道理"，而不是随机换了个推荐。推荐系统可解释性的前沿实践。

## 四、输出结构（给表现层/用户）

```json
{
  "top3": [
    {
      "rank": "🥇主推",
      "title": "麦香鱼 + 苹果片",
      "price_real": 22.13,
      "kcal": 357,
      "reasons": ["全餐约357kcal，在你700红线内只占一半", "鱼堡蛋白够、油炸少"],
      "counterfactual": "没推你常点的板烧四件套，因为配薯配翅一套900+，今天你要控700以内"
    }
  ],
  "benefit_alert": "你有 351.9 积分已过期，另有 2 张券今晚到期",
  "decision_trace_ref": "见 08 决策快照"
}
```

> 表现层把它翻译成自然、口语化的回复（见 SKILL 主纲"输出规范"），不要直接把 JSON 丢给用户。
